The Helix CLI is the `helix` command-line interface for scripting a running Helix editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, share HTML/Markdown artifacts, and control Helix-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → Helix CLI](/docs/settings). On Linux the command is `helix-ide`, because the Helix text editor can already own `/usr/bin/helix` — see [Install → Linux](/docs/install#linux).

Agents can install the matching Helix CLI skill with:

```bash
npx skills add https://github.com/bernardofernandezz/helix --skill helix-cli
# headless / no Settings UI:
helix skills install --skill helix-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable Helix skill, including `helix skills install` / `helix skills update`.

## Install & verify

```
command -v helix
helix status --json
```

## Worktree commands

```
helix worktree ps --json
helix worktree create --repo id:<repoId> --name my-task --issue 123 --json
helix worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
helix worktree current --json
helix worktree set --worktree active --comment "reproduced bug" --json
helix worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
helix worktree set --worktree active --pr null --json
helix worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [Helix CLI reference](/docs/cli/reference).

## Terminal commands

```
helix terminal list --json
helix terminal read --json
helix terminal send --text "continue" --enter --json
helix terminal wait --for tui-idle --timeout-ms 30000 --json
helix terminal create --worktree path:/projects/app --command "npm test" --json
helix terminal split --direction vertical --command "npm run dev" --json
```

For tracked multi-agent work, use [Orchestration](/docs/cli/orchestration) instead of plain terminal prompts.

## File commands

Open files and diffs as tabs in their Helix worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
helix file open src/App.tsx
helix file diff src/App.tsx --staged
helix file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `helix tab profile`; start with `helix tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `helix automations` to create, inspect, run, and remove scheduled Helix tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Share HTML or Markdown as public view links through the signed-in Helix account (`helix artifacts share|update|list|delete`). Publishing is **opt-in** under Settings → Artifacts. Command details: [CLI reference → Artifacts](/docs/cli/reference#artifacts).

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
helix goto --url https://example.com --json
helix snapshot --json     # returns refs like @e1, @e3
helix click --element @e3 --json
helix fill --element @e1 --value "user@example.com" --json
helix screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
helix set device --name "iPhone 12" --json
helix screenshot --json
```
